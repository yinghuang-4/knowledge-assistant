# 对照实验一：工具集（no_pet_care vs all）

> 数据来源于 `runs_a1..a3.csv`（A 组）与 `runs_b1..b3.csv`（B 组）；
> **本文件所有数字由 `eval/compare_ab.py` 生成，可复现**。
> 实验日期：2026-10-07 ｜ 对应任务：t37

## 0. 实验设计

**假设（跑之前写下，未事后修改）**

- **H1**：A 组（移除 MCP `pet_care`）通过率 **高于** B 组（暴露全部工具）
- **H2**：A 组跨轮方差 **小于** B 组

**自变量（只差这一个）**

| | 暴露的工具 |
|---|---|
| **A 组**（no_pet_care） | `add`、`search_knowledge`、`save_memory`、`load_memory` |
| **B 组**（all） | 上述 + **`pet_care`** |

**控制变量**

- 同一评测集（t33 建的 20 题：`in_kb` 8 / `should_refuse` 8 / `boundary` 4）
- 同一 runner、同一隔离三件套（每题独立 `thread_id`、评测专用 `MEMORY_FILE`、新 thread 预存 system）
- **同一判据版本**：P1 修正（匹配前 `normalize`）之后；B 组为**重判**结果（见「5. 判据修正的影响」）
- 各跑 **3 轮**（t35 已证明单轮结果受非确定性影响，不可用于对比）

**因变量**：通过率、检索发生率、`recall@k`、延迟、token

## 1. 对比表

| 指标 | **A 组**（no_pet_care） | **B 组**（all） | 差异 |
|---|---|---|---|
| 逐轮通过率 | 95% / 100% / 100% | 80% / 90% / 70% | — |
| **通过率均值** | **98.3%** | 80.0% | **+18.3 pt** |
| **极差（方差代理）** | **5 pt**（σ 2.4） | **20 pt**（σ 8.2） | **−15 pt** |
| **检索发生率** | **98.3%**（59/60） | 76.7%（46/60） | **+21.6 pt** |
| **`recall@k` 主口径** | **100%**（24/24） | 66.7%（16/24） | **+33.3 pt** |
| `recall@k` 仅检索题 | 100%（24/24） | 100%（16/16） | 0 |
| 平均 token（输入） | 2053 | 2127 | −74 |
| P50 / P95 延迟 | 1870 / 2390 ms | 1518 / 2001 ms | **+352 / +389 ms** |
| 出现过失败的题 | 仅 `q006` | 6 道（q003/q006/q009/q0010/q0012/q0019） | — |
| 通过率 95% 置信区间 | [91.1%, 99.7%] | [68.2%, 88.2%] | **不重叠** |

## 2. 假设检验

| 假设 | 结果 | 数据 |
|---|---|---|
| **H1** 通过率更高 | ✅ **支持** | 98.3% vs 80.0%（+18.3 pt） |
| **H2** 方差更小 | ✅ **支持** | 极差 5 pt vs 20 pt（σ 2.4 vs 8.2） |
| **机制** | ✅ **成立** | 检索发生率 76.7% → 98.3%（+21.6 pt） |

## 3. 结论（可辩护）

**① 两个假设都成立，而且方向与预测一致。**

**② 机制是清楚的因果链，不是巧合。**

移除 `pet_care` 之后，模型的**检索发生率从 76.7% 升到 98.3%**。这说明变化**不是**"模型变聪明了"，而是**少了一个省事的替代选项**：

> 移除 `pet_care` → 模型改走 `search_knowledge` → 检索发生率↑ → `recall@k` 主口径 66.7% → 100% → 通过率↑、跨轮方差↓

**四个指标（检索发生率、召回率、通过率、方差）同向变化，且都能由同一条机制解释**——这是结论可辩护的主要依据。

**③ 代价是明确的，而且划算。**

A 组 P50 延迟 1518 → **1870 ms（+352 ms）**，因为多了一次检索往返；但平均输入 token **反而略降**（2127 → 2053，移除了一个工具的 schema）。

> 结论：这是「**用约 0.35 秒换 18 个百分点通过率、并让波动收窄 15 个百分点**」的交易。在知识问答场景下明确划算。

**④ 只解决了一半：P0-B 依然存在。**

A 组 3 轮中**唯一**的失败是 `q006`（a1 那一轮），表现是：

```
pass=False  tools=0  检索块=0
答：这个问题我的知识库里没有资料，无法回答。
```

即 **零工具调用 + 无据声称「知识库里没有」**——正是 t36 问题清单里的 **P0-B**。

> **「保证信息来源只有一处」修好了 P0-A，对 P0-B 完全无效。**
> 模型在没有可赖的工具之后，仍然可以**不查就宣称没有**。

因此 t36 把 P0-A / P0-B 拆成两条是**必要的**——若并成一条，会误以为"删掉工具就完事"。**P0-B 必须单独修提示词。**

## 4. 已知限制（决定结论能被推多远）

**① 天花板效应：这套题对已修复的系统已接近失效。**

A 组 59/60 = 98.3%。若继续优化（改 `top_k`、改切块、调提示词），**这套 20 题大概率测不出差别**。

> 结论：t37 之后若还要做对照实验，**必须先扩充评测集**（题量、题型、难度），否则会得到"改什么都没用"的假象——那是**尺子的问题**，不是系统的问题。

**② 样本量小，比率不可当精确值引用。**

A 组 60 次里仅 1 次失败，95% Wilson 置信区间为 **[91.1%, 99.7%]**；B 组为 **[68.2%, 88.2%]**。

> 两组区间**不重叠**，所以"**A 优于 B**"这个方向可信；
> 但"**98.3%**"这个具体数字**不应被引用为精确值**（下界只有 91%）。

**③ 时间混淆（最重要的一条）。**

B 组数据采集于 **2026-10-03**，A 组采集于 **2026-10-07**。被测模型 `deepseek-chat` 是**在线服务**——若它在这 4 天内更新过，观察到的差异里就**混入了时间因素**，无法 100% 归因于工具集。

> 更严谨的做法：**A/B 交替跑**（a1、b1、a2、b2…），把时间因素随机化，而不是把两组分两天跑。
>
> 本条**不推翻结论**（机制解释有检索发生率同步佐证），但**降低了结论的强度**。这条正是"可辩护"与"过度自信"的分界线。

**④ 结论的适用边界。**

结论只对**这套 20 题 + 8 行知识库 + 当前提示词**成立。不能推广为"任何系统都该删掉冗余工具"——本例成立的前提是：**两个工具在回答同一类问题，且内容互相矛盾**（见 t36 问题清单 P0）。

## 5. 判据修正的影响（附带发现）

本实验开始前修好了 P1（`must_include` 匹配前做 `normalize`，见 t36 问题清单）。**用修正后的判据重判历史数据，60 行中仅 1 处判定变化**：

```
runs_r2.csv → 判定变化 1 处: [('r2', 'q009', 'False', 'True')]
```

- **只变了 1 处** → 说明修正**精准**，没有误伤其它题（若变化十几处，就说明改的是语义而非格式）
- **影响量化**：B 组通过率 **78.3% → 80.0%（+1.7 pt）**。这就是「判据缺陷」造成的测量误差
- 教学意义：判据修正后**只需重判、不必重跑模型**（`rejudge.py`）——**判定与生成分离**

## 6. 对 P0 修复决策的意义

- **推荐**：把 `pet_care` 的 3 条内容**并入知识库**（notes.txt / 向量库），让真相只有一个；MCP 工具形态可保留但不再承载宠物知识，或直接移除 `pet_care`
- **不推荐**：只改工具描述做消歧（补丁）——它只**降低选错概率**，两个源的内容冲突依然存在
- **本实验未覆盖**：只验证了"**移除** `pet_care`"的效果，**未验证"合并内容"**的效果（后者需要另一次实验）
