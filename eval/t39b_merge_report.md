## 1. 改了什么

**`pet_care` 从"持有数据"改为"查询知识库"**（无状态薄封装）：

```python
NOTES = os.path.join(os.path.dirname(os.path.abspath(__file__)), "notes.txt")

@mcp.tool()
def pet_care(topic: str) -> str:
    """查询宠物护理知识。topic 可传：牛奶、洋葱、发烧"""
    lines = [l.strip() for l in open(NOTES, encoding="utf-8") if l.strip()]
    grams = {topic[i:i+2] for i in range(len(topic) - 1)} or ({topic} if topic else set())
    hits = [l for l in lines if any(g in l for g in grams)]
    if not hits:
        return "pet_care 未匹配到「%s」，请改用 search_knowledge 查询知识库。" % topic
    return "\n".join(hits)
```

**三个设计要点**：

1. **2-gram 匹配**：中文无空格，整串匹配会因问法不同而失配。实测 `"39.5度算发烧吗"`、`"一小块洋葱会贫血吗"` 均正确命中
2. **兜底话术限定自身范围**：不说"知识库中没有"——**一个只做关键词过滤的工具没资格替整个知识库发言**
3. **`notes.txt` 未改动 → 向量库无需重建 → `golden_ids` 全部继续有效**

## 4. 结论

**① H3 成立：A′ 与 B′ 的差异 = 0.0 pt**（t37 时是 **18.3 pt**）。
> **"两个入口、一个真相"验证成功。**

**② P0-B 归零**（6.7% → **0/60**）——而且是**在保留 `pet_care` 的前提下**做到的。

**③ 最有力的证据在 B′ 的"未检索率 18.3%"**：

> B′ 里仍有约 **1/5 的行选择走 `pet_care` 而不是检索**，**而它们全部通过**。
> 这直接证明：**关键的从来不是"用哪个工具"，而是"两个工具说的是不是同一件事"。**
> 修复前，走错工具 = 拿到冲突内容 = 答错；修复后，**走哪条路都对**。

**④ 代价**：输入 token 2127 → **2597（+22%）**、P50 1518 → 1897 ms。
但对比 t39a 那笔交易（+21% token 换 +6.7pt 且**不显著**），**这笔是 +22% 换 +20pt 且 P0-B 清零**——划算得多。

**⑤ `t39c`（结构性强制检索）经评估取消**：P0-B 已 0/60，"硬保险"暂不需要；任务标记为 `skipped` 并留痕（若将来重现再启用）。
