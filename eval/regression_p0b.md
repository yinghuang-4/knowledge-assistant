# 回归记录：P0-B 提示词约束（t39a）

- 日期：2026-10-11
- 目标：约束「无据声称知识库里没有」（t36 问题清单 **P0-B**）
- 关联：`main.py` 的 `SYSTEM_PROMPT`（第 91 行）

## 1. 改了什么

**新增条款**（把"拒答"绑定到 `search_knowledge` 的返回上）：

```
知识类问题必须先调用 search_knowledge 查资料；
只有在 search_knowledge 明确返回「未找到相关资料」之后，才允许回答
『这个问题我的知识库里没有资料，无法回答』。
未调用 search_knowledge 时，绝对不允许声称「知识库里没有」「没有相关资料」。
search_knowledge 返回了内容时，必须基于返回内容回答，不得声称没有。
```

**同时补回三条被误删的规则**（改写时误伤，见 §5）：

- 「知识类问题和工具类问题都绝对禁止用自己的知识编造答案」
- 「工具类问题正常调用对应工具」
- 「**当用户说出值得长期记住的信息（名字、偏好、重要结论）时**，调用 `save_memory` 保存」（触发条件被删过）

## 2. 怎么测的

| 项 | 设置 |
|---|---|
| 自变量 | **只有提示词**（两组工具集都是全量 `all`） |
| 对照 | **B 组** = 旧提示词（`runs_b1..b3`，2026-10-07 采集）<br>**P 组** = 新提示词（`runs_p1..p3`，2026-10-11 采集） |
| 规模 | 各 **3 轮 × 20 题 = 60 行** |
| 判据 | 同一版本（P1 修正后） |

**P0-B 的操作定义**（本次修正过，见 §5）：

```
P0-B = 非 should_refuse 题  且  retrieved_ids 为空  且  refusal == True
     （即"该答的题"里，"没查就声称没有"）
```

> `should_refuse` 题的"未检索 + 拒答"是**期望行为**，不能计入。

## 4. 结论

1. **提示词确实降低了"不查"的倾向**：未检索率 23.3% → 15.0%（−8.3 pt）
2. **但 P0-B 没有修好**：6.7% → 5.0%，且 `q006`（「我的猫 39.5 度算发烧吗」，而知识库里明确有 38.0-39.2）在 P 组**三轮全部**复现
3. **通过率提升不显著**：+6.7 pt，但两组置信区间重叠
4. **代价明确**：输入 token **+21%**、P50 延迟 +10%
5. **无回归损害**：没有任何题"只在 P 组失败"

> **结论：提示词能改变行为倾向，但不能强制工具调用。**
> 模型仍可"决定不查"，然后照提示词里给的那句话拒答。
> **能用结构保证的事，不要交给提示词。** → 根治方案已新增为 **`t39c`：router 层对知识类问题强制先检索一次**。

## 5. 实验有效性的两个坑（本次踩到并修正）

**坑 ①：三轮不是同一种处理**

首跑 `runs_p1.csv` 生成于 **13:42:03**，而"补回三条规则"的改动发生在 **13:44:38** → **p1 用的是另一个版本**，与 p2/p3 不可合并。

> **"跑三轮"不等于"同一种处理跑三轮"。实验期间不许改变被测对象。**
> 抓出来的方式：比较 **数据文件生成时间 vs 源码修改时间**。已归档为 `archive/runs_p1_缺规则版本.csv` 并重跑。

**坑 ②：P0-B 的操作定义首版有缺陷**

初版定义为「未检索 且 拒答」，把 `p1/q002`（`should_refuse` 题）算了进去——**那是期望行为，不是 P0-B**。已修正为「非 `should_refuse` 题 且 未检索 且 拒答」。

> 这与学习者的错题 5（类型标注）、错题 6（"出现"vs"被断言"）**同族：判据的边界没划清**。
